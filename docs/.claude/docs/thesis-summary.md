# Выжимка из дипломной работы

> Источник: пояснительная записка к дипломному проекту.  
> Цель файла — доменный контекст для понимания бизнес-логики системы.

---

## Суть системы

**«Агрегатор взаимодействия граждан с организациями»** — SaaS-платформа онлайн-записи на услуги и управления деятельностью организаций.

Проблема: до автоматизации — бумажные журналы, мессенджеры, Excel. Нет стандарта, потери данных, ошибки.

---

## Пользователи системы

| Роль | Интерфейс | Основные действия |
|------|-----------|------------------|
| **Клиент (гражданин)** | Мобильное Android-приложение | Запись на услугу, просмотр статуса, получение QR-кода, уведомления |
| **Сотрудник организации** | Web-приложение | Обработка записей, управление расписанием, смена статусов |
| **Администратор платформы** | Web-панель | Модерация организаций, управление пользователями, системные настройки |

---

## Ключевые бизнес-процессы

### Создание записи (основной сценарий)
1. Клиент выбирает организацию → услугу → сотрудника → временной слот
2. Система проверяет доступность слота
3. Создаётся запись, генерируется QR-код
4. Клиент получает уведомление

**Альтернативы:** слот занят → к выбору; ошибка валидации → исправить данные.

### Управление расписанием
- Сотрудник задаёт шаблон (по дням недели) или конкретные рабочие дни
- Система генерирует слоты для записи
- Конфликт интервалов — ошибка

### Модерация организации
- Организация регистрируется → статус `pending`
- Администратор проверяет документы → `active` или `blocked`
- История решений сохраняется

## Доменные сущности

### Пользователи
- **Гражданин** — ФИО, контакты (телефон, email), auth-данные
- **Сотрудник организации** — ФИО, должность, принадлежность к организации/филиалу
- **Администратор платформы** — отдельная сущность, максимальные права

### Организации
- **Организация** — название, описание, контакты, юридические данные, статус
- **Филиал** — адрес, город, принадлежность к организации
- **Документ организации** — для модерации
- **Модерация организации** — решение + комментарий администратора

### Услуги
- **Категория услуги** — группировка
- **Услуга** — название, описание, продолжительность, стоимость, организация
- **Связь сотрудник–услуга** — какие услуги оказывает конкретный сотрудник

### Расписание
- **Шаблон графика** — типовое расписание по дням недели (время начала/конца)
- **График работы** — фактические рабочие дни на конкретные даты
- **Слот записи** — конкретный интервал (сотрудник + дата + время)

### Записи (Bookings)
- **Запись** — клиент + услуга + сотрудник + слот + статус
- **История статусов** — все изменения с временными метками
- **QR-код записи** — данные для генерации и валидации

### Уведомления
- **Уведомление** — тип + канал + текст + статус отправки
- **Push-токен устройства** — для FCM

### Справочники (статические таблицы)
- `organization_statuses` — pending, approved, rejected, blocked
- `booking_statuses` — создана, подтверждена, отменена, завершена
- `slot_statuses`
- `notification_channels` — email, push
- `notification_types`
- `moderation_actions`
- `moderation_decisions`

## Функциональные требования (из диплома)

1. Регистрация организаций + модерация администратором
2. Регистрация и авторизация граждан
3. Управление услугами и расписанием сотрудников
4. Создание записи → генерация QR-кода
5. Управление статусами записей
6. Push и email уведомления (FCM + SMTP)
7. Разграничение прав доступа сотрудников
8. История взаимодействий

---

## Нефункциональные требования

| Требование | Детали |
|-----------|--------|
| **Производительность** | Отклик < 2 сек при нормальной нагрузке |
| **Масштабируемость** | Архитектура допускает рост нагрузки без переписывания |
| **Безопасность** | Auth обязателен, защита персональных данных, RBAC |
| **Совместимость** | Мобильное приложение — Android; Web — современные браузеры |
| **Расширяемость** | Добавление функций без поломки существующих |

## Конкуренты (анализ из диплома)

| Продукт | Проблема |
|---------|---------|
| YCLIENTS | Узкая сфера услуг, избыточный функционал |
